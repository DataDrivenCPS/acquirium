App deployment and recovery#

Deploying an app can mean recomputing months of history. This guide shows how to see what a deployment will do before you make it, how to check on an app afterwards, how to change its code, and how to recover when a calculation fails. The examples continue from calculating a derived stream, on the sine-wave server.

Deployment preview#

Before switching wave-spread from ten-second buckets to a rolling window, ask what the change would do:

preview = client.deploy_app(app, dry_run=True)
preview["app"]["apps"]

{'wave-spread': {'operators': 1, 'groups': 23, 'input_rows': 78,
                 'cleared_rows': 5, 'changes': {'redefined': 1},
                 'downstream': False}}

Nothing has changed yet. The preview says the app would be redefined, which means its results are thrown away and recomputed: 23 windows to calculate, from 78 stored readings, replacing the 5 bucket results it has now. No other app reads its output, so nothing downstream is affected. On a real plant, the same numbers tell a change to one filter’s settings apart from a rebuild of a year of history.

The preview does not run your function, so it cannot tell you whether the function works. Try the function on a small frame first, as the calculation guide does.

Check preview["app"]["warnings"] as well. A selection that matches no streams is allowed, because the driver may not have registered them yet, but more often it means the query is narrower than you meant.

Deployment and status#

client.deploy_app(app)
state = client.inspect_app("wave-spread")["app"]
state["status"], state["error"], state["warnings"]

('active', None, [])

state["operators"] lists what is running: for each group, its input streams and the stream each output is written to. Deploying one app leaves the others in place.

The same steps work from the command line, given a file with a function that takes (client, parameters) and returns the App:

acquirium app deploy examples/transformation/threshold_app.py:high_wave --dry-run
acquirium app deploy examples/transformation/threshold_app.py:high_wave
acquirium app inspect high-wave --json

Calculation updates#

Edit the function file, rebuild the app with aq.PythonFunction.from_file(...), and deploy it again. The path can stay the same. Acquirium identifies the code by its content hash and saves a copy when you deploy. Editing or removing the original file does not change a running app.

Changed code creates a new calculation version and recomputes the app’s history. A preview shows how much work that involves. Redeploying identical code keeps the same version, even if its source path changes.

Recovery from a failed calculation#

Here is a function with a bug, saved as ratio.py. It divides by each reading, and the sine wave passes through zero:

from acquirium.functions import emit


def ratio(frame, context):
    return {"ratio": emit(context, 1 / frame["value"][0])}

Deploy it:

ratio_app = aq.App(
    name="wave-ratio",
    inputs={"wave": aq.Selection.from_query(wave, measurement="wave")},
    outputs={"ratio": aq.Output()},
    function=aq.PythonFunction.from_file(Path("ratio.py"), "ratio"),
    window=aq.Pointwise(),
)
client.deploy_app(ratio_app)["app"]["status"]

'failed'

The very first reading is zero, so the calculation fails. App inspection reports why:

print(client.inspect_app("wave-ratio")["app"]["error"])

execution failed: Python function failed: Traceback (most recent call last):
  ...
  File "/tmp/.tmpVdTlNB/function.py", line 5, in ratio
    return {"ratio": emit(context, 1 / frame["value"][0])}
                                   ~~^~~~~~~~~~~~~~~~~~~
ZeroDivisionError: float division by zero

Acquirium keeps this app’s last successful results and marks it failed, with stale=True. Apps that consume its outputs keep their results and become blocked. Their failures entries identify the failed upstream operators in blocked_by. A first execution that fails has no earlier results to retain.

Raw readings and unrelated apps continue updating. A published receipt confirms that the write was committed; check app status to see whether a calculation is current.

To recover, edit ratio.py:

from acquirium.functions import emit


def ratio(frame, context):
    value = frame["value"][0]
    if abs(value) < 1e-9:
        return {"ratio": emit(context, None)}
    return {"ratio": emit(context, 1 / value)}

Rebuild the declaration and deploy it:

fixed_app = aq.App(
    name="wave-ratio",
    inputs={"wave": aq.Selection.from_query(wave, measurement="wave")},
    outputs={"ratio": aq.Output()},
    function=aq.PythonFunction.from_file(Path("ratio.py"), "ratio"),
    window=aq.Pointwise(),
)
client.deploy_app(fixed_app)

A moment later the app is running:

client.inspect_app("wave-ratio")["app"]["status"]

'active'

Acquirium recomputes the failed branch from current inputs, including corrections and deletions received while it was blocked. Recovered results and downstream updates become visible together. Their failure status clears.

When the cause is outside the code, such as a missing package, fix that and call client.retry_engine(). This requests another attempt without requiring a new reading. A change to a failed operator’s inputs also triggers another attempt. Failure status and retained results survive a server restart.

App removal#

client.remove_app(name) removes an app and its current results. Earlier snapshots keep their history. Remove any apps that read its outputs first; the server refuses to remove an app something else depends on.
