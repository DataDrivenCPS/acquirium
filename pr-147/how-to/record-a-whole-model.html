Record a whole model#

In this article we’ll describe model adapters. A model adapter lists the values of a model that a study should record, with a function that reads each value. The study then declares all the variables in one call, and records all the values in one call.

This is useful for a model with many values, where declaring and recording them one by one takes a lot of code. Read the tutorial Running experiments first.

1. Build an adapter#

The examples use a small model of a pump, written in plain Python. It stands for your own model:

from datetime import datetime, timedelta, timezone

import acquirium as aq

acq = aq.init()


class PumpModel:
    def __init__(self):
        self.speed = 50.0          # Hz
        self.rated_power = 1100.0  # kW
        self.power = 0.0           # kW
        self.pressure = 0.0        # bar

    def step(self, hour):
        self.power = round(self.rated_power * (self.speed / 50) ** 3, 1)
        self.pressure = round(60 * (self.speed / 50) ** 2 + 0.5 * hour, 2)


model = PumpModel()

aq.adapters.define() creates an empty adapter. Each line below adds one value, with a read function that returns the current value from the model:

adapter = aq.adapters.define()

adapter.input.scalar("speed", read=lambda: model.speed, unit="Hz")
adapter.input.scalar("rated power", read=lambda: model.rated_power, unit="kW")
adapter.output.scalar("power", read=lambda: model.power, unit="kW")
adapter.output.timeseries("pressure", read=lambda: model.pressure, unit="bar")

  • adapter.input and adapter.output set the role of the variable.

  • The kinds are scalar(), text(), json(), table(), object() and timeseries().

  • A timeseries() value is read once per time step. The other kinds are read once per run.

frame() lists what the adapter declares, and preview() reads every value from the model. Both work without a study, so the adapter can be checked before anything is recorded:

print(adapter.frame().select("label", "role", "kind", "unit"))
print(adapter.preview())

2. Declare the variables in a study#

declare_from() declares every variable of the adapter in the study:

study = acq.study.define("pump-model")
variables = study.declare_from(adapter)

variables holds the declared variables together with their read functions. One variable is available as variables["power"].

3. Record the runs#

  • record_values() reads and records every value that is not a timeseries.

  • sample(at=time) reads and records one sample of every timeseries, with the given time.

The loop below records three runs. The inputs are recorded before the model runs, one sample is recorded at each step, and the outputs are recorded at the end:

start = datetime(2025, 7, 1, tzinfo=timezone.utc)

for hz in [40.0, 45.0, 50.0]:
    model.speed = hz
    run = study.start({"operator": "ana"})

    variables.input.record_values()
    for hour in range(3):
        model.step(hour)
        variables.sample(at=start + timedelta(hours=hour))
    variables.output.record_values()

    run.finish()

variables.input and variables.output select the variables of one role. variables.record_values() records both roles at once.

The Pyomo adapter#

aq.adapters.pyomo(model) is an adapter for Pyomo models, such as WaterTAP flowsheets. It needs Pyomo, which is installed with pip install "acquirium[pyomo]".

With this adapter a value is given as a Pyomo component instead of a read function. The unit and the description are taken from the component:

import pyomo.environ as pyo

model = pyo.ConcreteModel()
model.speed = pyo.Var(initialize=50, units=pyo.units.Hz, doc="Speed of the pumps")
model.flow = pyo.Var(["P1", "P2"], initialize=100, units=pyo.units.kg / pyo.units.s, doc="Flow of each pump")
model.power = pyo.Expression(
    expr=1100 * pyo.units.kW * (model.speed / (50 * pyo.units.Hz)) ** 3,
    doc="Power of the pumps",
)

adapter = aq.adapters.pyomo(model)
adapter.input.scalar("speed", model.speed)
adapter.output.scalar("power", model.power)
for var in model.flow.values():
    adapter.output.scalar(var.name, var)

print(adapter.frame().select("label", "role", "unit", "description"))

shape: (4, 4)
┌──────────┬────────┬──────┬────────────────────┐
│ label    ┆ role   ┆ unit ┆ description        │
│ ---      ┆ ---    ┆ ---  ┆ ---                │
│ str      ┆ str    ┆ str  ┆ str                │
╞══════════╪════════╪══════╪════════════════════╡
│ speed    ┆ input  ┆ Hz   ┆ Speed of the pumps │
│ power    ┆ output ┆ kW   ┆ Power of the pumps │
│ flow[P1] ┆ output ┆ kg/s ┆ null               │
│ flow[P2] ┆ output ┆ kg/s ┆ null               │
└──────────┴────────┴──────┴────────────────────┘

Note that an indexed component such as model.flow cannot be given as a whole. The loop adds one variable for each element of it. For a large model, a loop over model.component_data_objects(pyo.Var) adds every variable of the model in the same way.

The rest is the same as with the generic adapter. In this example the values are set by hand. In your own script the solver sets them:

study = acq.study.define("pump-pyomo")
variables = study.declare_from(adapter)

for hz in [40, 45, 50]:
    model.speed.set_value(hz)
    model.flow["P1"].set_value(2 * hz)
    model.flow["P2"].set_value(hz)

    run = study.start()
    variables.record_values()
    run.finish()

print(study.experiments.scalars())

Use a new model object#

The read functions of an adapter point to one model object. If your script builds a new model object, build a new adapter for it and call declare_from() again. The study keeps its variables, and the new variables object reads from the new model.
