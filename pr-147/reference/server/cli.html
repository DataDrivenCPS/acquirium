Command line#

The acquirium command starts the server and manages what runs on it. With uv, run it as uv run acquirium ....

command

what it does

acquirium server

start the server, with the drivers and apps of the config file

acquirium driver start

start the drivers of a config file on a running server

acquirium driver list

list the drivers running on a server

acquirium driver stop

stop one driver

acquirium app list

list the deployed apps

acquirium app inspect

show the details of one deployed app

acquirium app deploy

deploy an app or preview its plan

acquirium config init

write a starter acquirium.toml

acquirium migrate

copy registered raw readings from a legacy server

acquirium example init

create the files of the example plant

acquirium clear

erase the stored data of a data folder

Every command accepts --help.

acquirium migrate#

acquirium migrate --from legacy.toml --to escapement.toml [--dry-run]

Connects to the two running servers identified by the configuration files. Use --dry-run to check the endpoints and count the source streams and readings without writing. See copy legacy readings for setup, verification, and retry steps.

Choosing the server#

The driver and app commands talk to a server that is already running. They take the same three options to find it:

option

meaning

--config, -c <path>

an acquirium.toml; the address is read from its [driver] section (server_url, server_port), else from its [server] section (host, port). Without the option, ./acquirium.toml is used if it exists

--server-url <str>

server host. Default: driver.server_url of the config, else server.host, else 127.0.0.1

--server-port <int>

server port. Default: driver.server_port of the config, else server.port, else 8000

acquirium server#

acquirium server [--config PATH] [--host HOST] [--port PORT] [--reload] [--workers N] [--verbose]

Starts the server, then the drivers and the apps listed in the config file. The command keeps running until it is stopped with Ctrl+C.

option

meaning

--config, -c <path>

path to acquirium.toml (see server configuration)

--host <str>

host to listen on; overrides server.host

--port, -p <int>

port to listen on; overrides server.port

--reload

restart the server when the code changes, for development

--workers, -w <int>

number of worker processes. It must be 1, because the graph store can only be opened by one process

--verbose, -v

print DEBUG logs of Acquirium

If the config has server.enabled = false, no server is started. The drivers of the config are sent to the server named in its [driver] section, as acquirium driver start does.

acquirium server --config acquirium.toml

acquirium driver start#

acquirium driver start CONFIG [--server-url HOST] [--server-port PORT]

Starts every [[drivers]] entry of CONFIG on a running server, then exits. The drivers keep running on the server.

argument

meaning

CONFIG

path to an acquirium.toml with [[drivers]] entries. Required

The command exits with status 1 when the config has no drivers, when the server cannot be reached, or when a driver fails to start.

acquirium driver start acquirium.toml

acquirium driver list#

acquirium driver list [--config PATH] [--server-url HOST] [--server-port PORT]

Lists the drivers running on the server, or prints No drivers running.

acquirium driver stop#

acquirium driver stop --name NAME [--config PATH] [--server-url HOST] [--server-port PORT]

Stops one driver.

option

meaning

--name <str>

the driver name, as shown by acquirium driver list. Required

acquirium app list#

acquirium app list [--json] [--config PATH] [--server-url HOST] [--server-port PORT]

Lists the deployed apps with their status, grouping and number of bindings. Apps that matched nothing or failed to plan are listed too, with their error.

option

meaning

--json

print the raw result instead of the summary

acquirium app inspect#

acquirium app inspect NAME [--json] [--config PATH] [--server-url HOST] [--server-port PORT]

Shows the app declaration, selected inputs, output operators, and any warnings or failures.

argument or option

meaning

NAME

the app name, as shown by acquirium app list. Required

--json

print the raw result instead of the summary

acquirium app deploy#

acquirium app deploy SPEC [--dry-run] [--config PATH]

SPEC identifies an app declaration or factory, such as ./plant_apps.py:pump_power_kw. With --dry-run the server reports the plan and the expected work before activation. See App commands.

acquirium config init#

acquirium config init [PATH] [--force]

Writes a starter acquirium.toml with a local server and one example driver.

argument or option

meaning

PATH

the file to write, or a folder to put acquirium.toml in. Default acquirium.toml

--force, -f

overwrite the file if it exists

acquirium example init#

acquirium example init [PATH] [--step MINUTES] [--force]

Creates a folder with the files of the example plant, a seawater desalination plant. It does not start a server.

  • model.ttl is the plant model.

  • data.csv is the data of the plant for the year 2025, with a time column and one column per stream.

argument or option

meaning

PATH

the folder to create. Default example

--step <int>

minutes between two rows of data.csv. Default 60

--force, -f

overwrite the two files if they exist

 
acquirium example init

Wrote example/model.ttl
Wrote example/data.csv (8760 rows, 32 streams)

The files are used in 5 - A Full Example.

acquirium clear#

acquirium clear [PATH] [--all] [--yes] [--config PATH]

Erases the stored data of a data folder: the graph, the readings and everything else in it. The embeddings of the text matcher are kept, because they take long to build and do not depend on your data. It does not start a server.

argument or option

meaning

PATH

the data folder to clear. Default: server.data_dir of the config, else .acquirium in the current folder

--all

also erase the embeddings, by removing the whole folder

--yes, -y

do not ask for confirmation

--config, -c <path>

an acquirium.toml; without it, ./acquirium.toml is used if it exists

The command exits with status 1 and erases nothing when:

  • a server is using the folder. Stop it first.

  • the folder does not look like an Acquirium data folder.

  • the confirmation is declined.

acquirium clear

Erase the stored data in /home/you/my-plant/.acquirium? [y/N]: y
Cleared /home/you/my-plant/.acquirium

The command leaves PostgreSQL databases and files outside the selected folder available. It reports when the configuration points to one of those locations.
