This page introduces the key concepts used in the rest of the tutorial.

## Architecture

Acquirium has two parts:

- The **server** stores everything and answers your queries.
- The **client** is the Python module you use to talk to the server from scripts, notebooks etc.

The simplest way to get both is `aq.init()`:

```python
import acquirium as aq

acq = aq.init()     # starts a server and returns a client
...
aq.shutdown()       # stops the server
```

`aq.init()` starts a server on your machine and keeps the data in a folder named `.acquirium`, in your working directory.
The data is persistent among runs. 

The server can also be started on its own with the `acquirium` command (see the [CLI reference](../reference/server/cli.md)).
This tutorial only uses `aq.init()`.

#### Text matcher

The server has a text matcher, so you can write plain text such as "mg/L" instead of RDF terms.

- By default, only exact names and symbols are matched.
- With `aq.init(exact_only=False)`, close matches are found as well, using a small embedding model. The first run takes a few minutes to download the model and prepare it. Later runs are faster.

## Data model

Acquirium stores two kinds of things:

- **Streams** are timeseries data: rows of `(time, value)`, typically generated by sensors or lab measurements. They are kept in the timeseries store, which is a relational database.
- **Metadata** describes the streams and the plant they come from. It is kept in the graph store.

### Streams

Each stream has to be registered to Acquirium before data is inserted into it.
A stream is registered with two names that you choose:

- `source_id` names where the data comes from, such as a script, a data logger or a CSV file. All streams coming from the same place share one `source_id`.
- `stream_name` names one stream of that source, such as a column header or a sensor tag. It has to be unique within its source.

For example, the script in [Getting started](../getting-started.md) registers the stream `temperature` under the source `check`.

Acquirium then generates a deterministic `stream_uri` from these two names.
Acquirium uses it internally to identify the data of the stream.
You keep using `source_id` and `stream_name` when you insert data.

### Metadata

The metadata in the graph store serves the following purposes:

- It describes the plant: which equipment is there and how it is connected. This is the **plant model**.
    - Having a plant model is optional.
    - If you want to build your own plant model, we recommend using the [metadata-annotator](https://github.com/DataDrivenCPS/metadata-annotator).
- It records which **property** is measured at which part of the plant, and which stream holds the data of that property. A property is one measured quantity, such as the outlet pressure of a pump.
    - If your plant model has property nodes, you can connect your streams to them.
    - This is explained in [TODO]().
- It holds the key metadata of streams, such as the unit and the quantity kind (what is measured, for example pressure).
    - This metadata is attached to the property of the stream.
    - If a stream is not connected to a property, Acquirium creates a property node for it and attaches the metadata there.
    - You can connect any registered stream to a property of your plant model later.
